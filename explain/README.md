## 1) المشروع ده بيعمل إيه أصلًا؟

ببساطة، **Edu Advisor** نظام بيساعد طالب كلية الحاسبات والمعلومات يعرف المواد اللي ممكن يسجلها في الترم الجاي. بدل ما الطالب يقعد يراجع كل المواد والمتطلبات السابقة بنفسه، النظام بياخد بياناته الأكاديمية وبيطلعله ترشيحات بالمواد المناسبة، مع أسباب الترشيح وبعض التنبيهات.

البيانات اللي بنحتاجها عادةً: السنة الدراسية، آخر ترم خلصه، الترم اللي عايز يسجل فيه، التخصص، الـ GPA، المواد اللي نجح فيها، والمواد اللي رسب فيها. فيه طريقتين لإدخال المواد: يدويًا، أو برفع كشف درجات PDF واستخراج البيانات منه **مع مراجعتها قبل الاعتماد عليها**.

**مهم جدًا:** ده نظام مساعد للقرار، مش بديل عن المرشد الأكاديمي أو اللائحة الرسمية.

## 2) إحنا وصلنا لفين؟

في البداية كانت الواجهة معمولة بـ **Streamlit**. بعد كده اتعملت نسخة **FastAPI** عشان أي تطبيق موبايل أو ويب يقدر يطلب البيانات عن طريق Endpoints ويرسم الواجهة بنفسه.

الفكرة إن الـ Backend **مش بيرسم أزرار وجداول زي Streamlit**؛ هو بيرجع JSON فيه البيانات، والـ Application هو اللي بيعرضها بالشكل اللي يناسبه. أما تصدير التقرير فبيرجع ملف PDF.

```text

Application (Mobile / Web)

         |

         | HTTP Request

         v

FastAPI (main.py)

         |

         +----> services.py (PDF / GPA / Reports)

         |

         +----> recommender.py (ترشيح المواد)

                       |

                       v

                   data/*.json

         |

         v

JSON Response / PDF File

```

### تحديث 26 أكتوبر — واجهة Streamlit لسه موجودة

فيه مسارين للاستخدام، ومهم نفرق بينهم:

- **Streamlit (`streamlit_app.py`)**: واجهة اختبار وتشغيل تفاعلية مباشرة؛ فيها تبويبات **Recommendations** و**GPA Calculator** و**Course Catalog** و**Academic Rules**. بتستدعي `EduAdvisor` مباشرة من Python، مش لازم تمر على FastAPI.
- **FastAPI (`main.py` + `services.py`)**: واجهة HTTP لأي تطبيق ويب أو موبايل؛ بتعرض الـ Endpoints وبترد JSON أو PDF. وجودها لا يعني إن الـ API منشور على الإنترنت.

النسختان بتخدمان نفس فكرة المشروع، لكن مش لازم تكون كل خاصية أو طريقة حساب مطابقة بينهما تلقائيًا. **أي تغيير في واحدة لازم يتراجع تأثيره على التانية.**

في Streamlit، الطالب بيختار **Academic Year (1–4)** و**Last Completed Semester** و**Target Semester** و**Department / Specialization**. وبعد كده يختار إدخال المواد يدويًا أو يرفع PDF. في حالة أول سنة/أول ترم بدون فصل سابق، البيانات السابقة والـ GPA مش مطلوبة. وبيظهر ملخص الساعات والمواد والتوصيات وإمكانية تنزيل تقرير PDF عند تثبيت `reportlab`.

**ملحوظة:** نسخة Streamlit الحالية اللي اتراجعت بتستدعي `advisor.recommend(..., current_semester=int(target_semester))`، وبالتالي الترم المستهدف هو اللي بيحدد التوافر في محرك الترشيح؛ اختيار آخر ترم مكتمل حقل منفصل للسجل الأكاديمي.

## 3) الملفات المهمة، وكل ملف مسؤوليته إيه؟

```text

edu_advisor_fastapi/

├── main.py

├── recommender.py

├── services.py

├── requirements.txt

├── README.md

└── data/

    ├── bylaws_courses.json

    ├── bylaws_prerequisites.json

    └── bylaws_rules.json

```

**`main.py`:** ده باب الدخول للـ API. فيه تعريف الـ Endpoints، وفحص البيانات اللي جاية من التطبيق، وتجهيز الـ Response. لو التطبيق بيبعت طلب ترشيح، الملف ده بيستقبله ويوصله للمحرك.

**`recommender.py`:** ده قلب المشروع. بيحدد المادة ينفع تتاخد ولا لأ، ويحسب أولوية المواد، ويختار المواد اللي هتظهر في التوصيات. **ماتعدّلش فيه من غير ما تفهم تأثير التغيير على كل الحالات.**

**`services.py`:** فيه الخدمات المساعدة، زي استخراج البيانات من PDF، تجميع محاولات النجاح والرسوب، حساب GPA من الدرجات الرقمية، وتجهيز تقرير التوصيات PDF.

**`bylaws_courses.json`:** كتالوج المواد: الكود، الاسم بالعربي والإنجليزي، الساعات، المستوى، النوع، والتصنيف.

**`bylaws_prerequisites.json`:** المتطلبات السابقة. مثلًا `CS142` محتاجة `CS141`، و`CS211` محتاجة `CS241` حسب البيانات الحالية.

**`bylaws_rules.json`:** بيانات اللائحة: عدد ساعات التخرج، حدود الساعات، الـ GPA، الأقسام، ومتطلبات التخرج. **خلي بالك:** مش كل قيمة موجودة هنا مطبقة تلقائيًا بنفس الشكل في الكود؛ فيه قواعد مكتوبة بشكل مباشر في Python.

**`requirements.txt`:** المكتبات المطلوبة للتشغيل.

## 4) تشغّل المشروع عندك إزاي؟

افتح فولدر الـ FastAPI في VS Code، وافتح Terminal، وبعدها نفّذ:

```powershell

py -m venv .venv

.\.venv\Scripts\Activate.ps1

python -m pip install -r requirements.txt

python -m uvicorn main:app --reload

```

لو PowerShell منع تشغيل ملف التفعيل، ممكن تستخدم Python بتاع البيئة مباشرة:

```powershell

.\.venv\Scripts\python.exe -m pip install -r requirements.txt

.\.venv\Scripts\python.exe -m uvicorn main:app --reload

```

بعد التشغيل افتح:

- `http://127.0.0.1:8000/docs` — هنا هتلاقي كل الـ Endpoints وتقدر تجربها.

- `http://127.0.0.1:8000/api/v1/health` — تتأكد إن السيرفر شغال.

**ملحوظة:** `127.0.0.1` ده عنوان جهازك إنت. عشان التطبيق يشتغل مع مستخدمين من برّه جهازك، لازم تنشر الـ Backend على استضافة وتاخد رابط HTTPS عام. أمر `--reload` للتطوير بس، مش للإنتاج.

## 5) الـ Endpoints الموجودة حاليًا

كل المسارات دي بييجي قبلها `/api/v1`:

| الطلب | المسار | بيعمل إيه؟ |

|---|---|---|

| GET | `/health` | يطمنك إن الخدمة شغالة |

| GET | `/config/options` | اختيارات السنة والترم والتخصص |

| GET | `/courses` | يجيب المواد، وممكن تبحث أو تفلتر |

| GET | `/courses/{course_id}` | تفاصيل مادة ومتطلباتها |

| GET | `/academic-rules` | بيانات اللائحة |

| GET | `/prerequisites` | خريطة المتطلبات السابقة |

| POST | `/transcripts/extract` | يستقبل كشف درجات PDF ويستخرج بياناته |

| POST | `/transcripts/attempts` | يرجع محاولات المواد بالترتيب |

| POST | `/transcripts/summary` | ملخص النجاح والرسوب والمحاولات |

| POST | `/recommendations` | يطلع التوصيات الكاملة |

| POST | `/recommendations/advisories` | التنبيهات الأكاديمية |

| POST | `/students/academic-summary` | ملخص حالة الطالب |

| POST | `/registration/limits` | حدود الساعات المستخدمة في الترشيح |

| POST | `/gpa/semester` | حساب GPA للترم |

| POST | `/gpa/cumulative` | تقدير الـ Cumulative GPA |

| POST | `/recommendations/export` | يرجع تقرير التوصيات PDF |

**مش معنى إن فيه Endpoint لكل جزء إن التطبيق لازم يناديهم كلهم في كل شاشة.** مثلًا `/recommendations` بيرجع التوصيات وملخص الطالب والتحذيرات في Response واحد، وده غالبًا كفاية لشاشة التوصيات.

## 6) رحلة الطالب من أول ما يفتح التطبيق

**الحالة الأولى — الطالب هيدخل بياناته يدوي:**

1. التطبيق يطلب `/config/options` عشان يملأ اختيارات السنة والترم والتخصص.

2. يطلب `/courses` عشان يعرض قائمة المواد.

3. الطالب يختار المواد اللي نجح ورسب فيها، ويدخل الـ GPA.

4. التطبيق يبعت البيانات لـ `/recommendations`.

5. الـ Backend يرجع `student` و`status` و`recommendations` و`registration_messages`، والتطبيق يعرضهم.

**الحالة التانية — الطالب هيرفع كشف درجات:**

1. التطبيق يبعت الملف لـ `/transcripts/extract` في خانة اسمها `file`.

2. الـ Backend يحاول يستخرج أكواد المواد، حالة كل محاولة، وبعض قيم الـ GPA.

3. **لازم التطبيق يعرض شاشة مراجعة**؛ لأن قراءة الـ PDF مش مضمونة 100%.

4. بعد تأكيد البيانات، التطبيق يبعت المواد والـ GPA وسجل `attempts` لـ `/recommendations`.

5. الـ Backend يرجع التوصيات والتنبيهات.

**مهم:** النسخة الحالية **مش بتخزن كشف الطالب بين الطلبات في Database أو Session**. التطبيق لازم يحتفظ بنتيجة الاستخراج مؤقتًا ويبعت البيانات المطلوبة في الطلب اللي بعده.

## 7) مثال Request للتوصيات

ده مثال توضيحي على شكل الطلب، **مش بيانات طالب حقيقي**:

```json

{

  "student_id": "TEST-001",

  "academic_year": 2,

  "last_completed_semester": 2,

  "target_semester": 1,

  "specialization": "IS",

  "gpa": 2.75,

  "passed_courses": ["CS101", "CS141"],

  "failed_courses": ["BS101"],

  "attempts": []

}

```

- `academic_year`: من 1 لـ 4.

- `last_completed_semester`: آخر ترم الطالب خلصه.

- `target_semester`: الترم اللي عايز يسجل فيه؛ `1` خريف، `2` ربيع، `3` صيفي.

- `specialization`: في الـ API الحالي: `General` أو `IS` أو `CS` أو `AI`.

- `passed_courses` و`failed_courses`: أكواد مواد موجودة فعلًا في الكتالوج، ومينفعش المادة تكون في القايمتين مع بعض.

- `attempts`: سجل المحاولات المستخرج من كشف الدرجات لو موجود.

**حالة الطالب الجديد:** لو سنة أولى، الترم المستهدف الأول، ولسه مخلصش أي ترم، يبقى `last_completed_semester` = `null`، والـ Backend بيعتبره طالب جديد من غير مواد سابقة وGPA سابق.

## 8) الترشيح بيحصل إزاي جوه `recommender.py`؟

الترشيح مش AI Model بيتدرب على بيانات؛ هو **Rule-Based Recommendation Engine** بيعتمد على بيانات المواد والقواعد اللي اتكتبت.

**أول خطوة — تحميل البيانات:** الكلاس `EduAdvisor` بيقرأ ملفات JSON، ويعمل فهارس للمواد والمتطلبات السابقة. من أهمها `prereq_map` اللي بتقول كل مادة محتاجة إيه، و`unlocks` اللي بتقول مادة معينة هتفتح أنهي مواد بعد كده.

**تاني خطوة — التحقق من صلاحية المادة:** الدالة `_check_eligibility()` بتستبعد المادة اللي الطالب نجح فيها، وبتشوف المتطلبات السابقة للمواد الجديدة. أما المادة اللي الطالب رسب فيها، فالمحرك الحالي بيسمح بترشيحها كإعادة لو متاحة في الترم، حتى لو بيانات المتطلب القديم ناقصة.

**تالت خطوة — هل المادة متاحة في الترم؟** الدالة `get_course_availability()` حاليًا **بتفترض** إن كل المواد متاحة في الخريف والربيع، ومواد المستوى الرابع متاحة كمان في الصيفي. **ده افتراض في الكود، مش جدول طرح المواد الحقيقي.**

**رابع خطوة — حساب الأولوية:** الدالة `_score_course()` بتحسب Score داخلي حسب عوامل زي: المادة إعادة ولا لأ، إجباري ولا اختياري، قريبة من مستوى الطالب ولا لأ، الـ GPA، وبتفتح كام مادة بعد كده.

**خامس خطوة — الترتيب النهائي:** الدالة `recommend()` بترتب مواد الإعادة الأول، وبعدها باقي المواد حسب أولوية التصنيف، وبعدها الـ Score. يعني **الـ Score مش العامل الوحيد اللي بيحدد الترتيب**.

**سادس خطوة — اختيار المواد:** المحرك بيحط مواد الإعادة المتاحة أولًا، وبعدين يضيف مواد تانية على قد حدود الساعات. خلي بالك: **مواد الإعادة ممكن تتجاوز الحد الأقصى أو عدد المواد المطلوب** حسب التصميم الحالي؛ وده لازم يتراجع أكاديميًا.

## 9) الرسوب المتكرر بيتحسب إزاي؟

لو كشف الدرجات فيه سجل المحاولات، `summarize_attempts()` بتجمع المحاولات لكل مادة.

مثال:

```text

CS211 -> Failed

CS211 -> Failed

```

هنا ممكن يظهر تحذير إن المادة اترسب فيها مرتين، **بشرط إن آخر محاولة مسجلة تكون Failed**.

لكن لو:

```text

CS211 -> Failed

CS211 -> Failed

CS211 -> Passed

```

التحذير مش هيظهر؛ لأن آخر محاولة نجاح. ولو آخر محاولة حالتها `unknown`، التحذير ده برضه مش بيظهر.

**التحذير استشاري بس:** مش بيمنع المادة من التوصيات، ومش بيغير أولوية محرك الترشيح. ماتخلطش بين **التحذير** وبين **قواعد السماح بالتسجيل**.

### تفاصيل إضافية في Streamlit — استخراج كشف الدرجات

- `normalize_course_code()` بتنظف أكواد المواد للمطابقة.
- `extract_course_attempts()` بتحاول تستخرج كل محاولة بترتيب ظهورها في صفحات الـ PDF، وتتعامل مع العلامات `X` للرسوب و`Y` أو `¥` للنجاح؛ بعض المحاولات بتفضل `unknown` وبتحتاج مراجعة.
- واجهة PDF بتعرض **سجل المحاولات** و**عدد مرات النجاح والرسوب لكل مادة**، وتحسب حالة المادة من آخر محاولة معروفة.
- لو اتعرف GPA من النص، الواجهة بتعرض **Cumulative GPA** و**Term GPA** للمراجعة. الاستنتاج من ترتيب الأرقام مش مضمون مع كل أشكال كشوف الدرجات.
- `get_repeated_failure_advisories()` بتنبه لو مادة اترسب فيها مرتين أو أكتر وآخر محاولة رسوب؛ التنبيه مش منع تسجيل.
- ملفات PDF المصورة (Scanned) ممكن مايتستخرجش منها نص، والنسخة اللي اتراجعت لا تضمن OCR تلقائي.

## 10) حساب الـ GPA

في المشروع طريقتين مختلفتين لازم تفرق بينهم:

**GPA Calculator في الـ API:** بياخد درجة رقمية من 0 لـ 100 لكل مادة، ويحولها لنقاط باستخدام `percentage_to_points()` في `services.py`، وبعدها يعمل متوسط مرجح بالساعات.

**حساب الـ GPA جوه المحرك:** الدالة `calculate_gpa()` في `recommender.py` بتتعامل مع **تقديرات حرفية** زي `A` و`B+` و`F` باستخدام جدول `grade_points` من اللائحة، لما البيانات دي تكون متاحة.

الاتنين مش نفس طريقة الإدخال، ولازم قبل أي تعديل نتأكد إن التحويلات مطابقة للائحة المعتمدة. حساب الـ Cumulative GPA الحالي **تقديري**، خصوصًا في حالات إعادة المواد أو استبعاد درجات قديمة.

### GPA Calculator في Streamlit

في تبويب **GPA Calculator** الطالب بيختار المواد، ويدخل الدرجة الرقمية من 0 إلى 100 لكل مادة. `percentage_to_grade_points()` داخل واجهة Streamlit بتحول الدرجة لنقاط وفق جدول موجود مباشرة في الكود، وبعدها بتحسب:

- **Semester GPA**: مجموع (نقاط المادة × ساعاتها) ÷ مجموع ساعات مواد الترم.
- **Semester Average (%)**: متوسط النسب المئوية مرجحًا بساعات المواد.
- **Estimated Cumulative GPA**: دمج الـ GPA السابق وساعاته مع نقاط وساعات الترم الحالي.

**تنبيه مهم:** جدول التحويل الرقمي داخل Streamlit مش بالضرورة مطابق لجدول التقديرات الحرفية في `bylaws_rules.json`، فلازم مطابقة الحسابات مع اللائحة قبل اعتمادها رسميًا.

## 11) اللائحة والساعات — خد بالك من النقطة دي

ملف `bylaws_rules.json` فيه مثلًا:

- إجمالي ساعات التخرج: **144 ساعة**.

- أقل GPA للتخرج: **2.0**.

- الحد العادي للساعات: **12 إلى 18 ساعة**.

- الصيفي في الملف: **6 إلى 12 ساعة**.

- فيه قواعد إنذار أكاديمي وإعادة مواد.

لكن **التطبيق الحالي مش بيطبّق كل التفاصيل دي بشكل موحّد**. مثلًا عند GPA أقل من 2، النسخة الحالية بتثبت الحد الأدنى عند 12، وبتستخدم حد أقصى كبير جدًا بدل حد 18 العادي. وكمان حدود الصيفي والإنذار مش متطبقة بالكامل في نفس مسار التوصيات.

**ممنوع نصلّح الاختلاف ده بالتخمين.** لازم نرجع لمسؤول أكاديمي أو نص اللائحة المعتمد، وبعدها نغير الكود ونضيف اختبارات.

## 12) لو عايز تعدّل حاجة، تروح فين؟

| عايز تعمل إيه؟ | تراجع أنهي ملف أو دالة؟ |

| تغير شروط صلاحية المادة | `_check_eligibility()` في `recommender.py` |

| تغير تحذير الرسوب المتكرر | `summarize_attempts()` |

| تغير شكل Request أو Response | `main.py`، مع تنسيق مع فريق التطبيق |

**نصيحة مهمة:** قبل ما تغير أي حاجة، شغّل مثال طالب وسجّل نتيجته. وبعد التعديل شغّل نفس المثال وقارن؛ عشان تعرف هل التغيير أثّر على مواد تانية من غير قصد.

## 13) حاجات لسه ناقصة أو محتاجة مراجعة

1. **طرح المواد حسب الترم:** النظام بيعتمد على افتراض عام؛ محتاج جدول طرح فعلي لو هنستخدمه للتسجيل الحقيقي.

2. **اختلاف التخصصات:** ملف اللائحة فيه `IT`، لكن اختيارات الـ API الحالية فيها `AI` ومفيهاش `IT`؛ لازم يتحدد المطلوب رسميًا.

3. **قراءة PDF:** بتعتمد على نص قابل للاستخراج وعلامات معينة (`X` للرسوب و`Y` أو `¥` للنجاح). ملفات الـ Scan محتاجة OCR أو مراجعة يدوية.

4. **استخراج GPA من PDF:** بيعتمد على ترتيب أرقام معينة في النص؛ لازم المستخدم يراجع القيمة.

5. **التخرج:** فحص أهلية التخرج الحالي بيعتمد أساسًا على الساعات والـ GPA، مش مراجعة كاملة لكل المجموعات الإجبارية والاختيارية.

6. **الخصوصية:** مفيش Login أو Authentication أو Database في النسخة الحالية؛ ماينفعش نستخدم كشوف درجات حقيقية على API عام من غير حماية.

7. **العربي في PDF:** الخطوط الافتراضية ممكن ما تعرضش العربي صح؛ محتاج دعم Unicode وRTL مناسب.

8. **جودة البيانات:** لازم نتأكد إن كل كود متطلب سابق موجود في الكتالوج وإن القواعد متوافقة مع نسخة اللائحة.

## 14) قبل ما تعمل Deploy على سيرفر

- جرّب الـ API محليًا من `/docs`.

- ارفع الكود على GitHub **من غير** كشوف درجات حقيقية أو كلمات سر.

- جهّز استضافة تدعم Python وHTTPS.

- ظبّط `ALLOWED_ORIGINS` لو فيه Web Frontend؛ ده إعداد CORS، **مش بديل عن الحماية**.

- أضف Authentication، وحدود للطلبات والملفات، وتسجيل أخطاء من غير بيانات شخصية.

- جرّب رفع PDF والتوصيات وتصدير التقرير على السيرفر.

- سجّل رابط الـ API وطريقة التحديث والرجوع لنسخة سابقة في مكان الفريق يقدر يوصل له.

## كلمة أخيرة للي هيكمل المشروع

المشروع ده مش مجرد كود بيطلع قايمة مواد. أي تغيير صغير في متطلب سابق أو شرط ساعات ممكن يأثر على قرار تسجيل طالب. عشان كده **افهم القاعدة، جرّبها، وثّق التغيير، وراجعها مع المسؤول الأكاديمي** قبل ما تعتمدها.

لو حاجة مش واضحة، ارجع للأصل: ملفات البيانات، ثم `recommender.py`، ثم الـ API في `main.py`. والأهم: **ما تعتبرش إن النتيجة صح لمجرد إن الـ Endpoint رجّع `200 OK`.**
